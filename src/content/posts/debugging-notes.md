> 기술 글의 구성을 보여주는 예시입니다. 실제 경험을 바탕으로 내용을 교체해주세요.

오래 걸려 해결한 문제도 시간이 지나면 과정을 잊어버립니다. 다음에 같은 문제를 만났을 때 도움이 되도록 기록의 구조를 미리 정해두면 좋습니다.

## 현상과 재현 조건

기대한 동작과 실제 동작을 나누어 적습니다. 실행 환경과 입력값도 함께 남겨야 다른 사람이 같은 상황을 확인할 수 있습니다.

| 항목 | 기록할 내용 |
| --- | --- |
| 기대한 결과 | 원래 어떤 동작을 기대했는가 |
| 실제 결과 | 어떤 오류나 차이가 생겼는가 |
| 재현 방법 | 최소한의 어떤 단계로 확인할 수 있는가 |

## 가설과 확인

추측과 확인된 사실을 구분합니다. 한 번에 하나의 조건을 바꾸면 무엇이 결과에 영향을 주었는지 파악하기 쉽습니다.

```text
가설 → 작은 실험 → 결과 확인 → 다음 가설
```

## 해결과 남은 질문

해결 방법에 이어 그 방법을 선택한 이유를 적습니다. 다른 선택지가 있었다면 어떤 제약 때문에 제외했는지도 남깁니다.

모든 질문에 답을 찾지 못했어도 괜찮습니다. 남은 질문은 다음 기록의 출발점이 됩니다.
